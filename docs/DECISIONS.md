# Implementation decisions

Material choices made while implementing `MVP.md`, with the reasoning. Product scope was not changed; these fill gaps or pick among allowed options. Requirement IDs refer to the acceptance matrix in `MVP.md`.

## Toolchain and versions

| Decision | Rationale |
| --- | --- |
| Node 22.22.0, pnpm 10.28.0, Nx 23.2.1 (integrated `project.json` layout), TypeScript 5.9.3 | Mutually compatible stable set verified against npm peer ranges on 7 Oct 2026. Angular 22 needs TypeScript 6 and a newer Node patch; NestJS 12 is outside the Nx 23 support range. |
| Angular 21.2 (standalone, zoneless, signals) + Angular Material 21.2 with the M3 `mat.theme` API | Default UI library per `AGENTS.md`; zoneless is the Angular 21 default. Icons are inline SVG paths registered in `MatIconRegistry`, and fonts use the system stack, so the dashboard has no CDN dependency and works offline in Docker. |
| NestJS 11.2 with Zod (`nestjs-zod` kept only as a dependency; validation runs through a small `zodBody` pipe) | Contracts are Zod schemas shared by API and UI (`libs/contracts`), giving one source of truth for limits and DTOs. |
| Prisma 7.10 with the `prisma-client` generator and `@prisma/adapter-pg` | Prisma 7 requires a driver adapter; generated client is git-ignored and regenerated by `pnpm db:generate`. |
| Jest 30 (unit + integration), Playwright 1.63 (critical journeys), ESLint 10 flat config | Required by the specification. Integration tests run against a real PostgreSQL database (`TEST_DATABASE_URL`) with migrations applied by a global setup. |
| XLSX handled by a small in-repo reader/writer on `fflate` + `fast-xml-parser` | The npm `xlsx` package has unpatched advisories and `exceljs` is unmaintained; the subset Raaye needs (inline strings, numbers, formulas detection) is small and fully tested. |
| `libphonenumber-js/max` for phone normalization | Required for correct E.164 handling of Pakistani and international numbers. |
| No `whatsapp` Node SDK | A typed `fetch` adapter (`meta.provider.ts`) keeps payloads explicit and testable. |

## Architecture

- **Three libraries, three apps.** `libs/contracts` (schemas and DTOs), `libs/domain` (pure rules: edit windows, consent derivation, selection validation, aggregates, CSV/XLSX, phone, copy), `libs/server` (NestJS modules, persistence, jobs, messaging, conversation engine, reporting, seed). `apps/api` is thin controllers, `apps/worker` runs the job loop and CLI commands, `apps/web` is the dashboard.
- **Tenant scoping by construction.** `createTenantDb(prisma, organizationId)` is a Prisma `$extends` client that injects `organizationId` into every `where`, `data`, `create` and `upsert` of every tenant-owned model and refuses control-plane models (`User`, `WebhookQuarantine`, `SimulatorState`). Controllers and domain modules only receive this scoped client through `TenantDbFactory`. The unscoped `PrismaService` is used only by documented control-plane helpers (membership resolution, app-key → connection lookup, due-job claims, retention sweeps, seed). Composite foreign keys `(organization_id, parent_id)` make cross-tenant relation connects impossible at the database level (R07, R08).
- **Durable PostgreSQL jobs.** One `jobs` table with `FOR UPDATE SKIP LOCKED` claims, leases, bounded retries with jittered exponential backoff, priorities (opt-outs first) and dedupe keys. The same handlers run in the worker loop, in `POST /internal/jobs/:id/execute` (Cloud Tasks) and in the simulator "drain" button. Deadlines (activation, closing, edit windows) are persisted, never kept in memory (R25-R27, R33).
- **Provider-neutral messages.** The planner produces `RenderedMessage` values (text, buttons, list, flow, template); adapters translate them. The mock adapter injects faults from persisted simulator state; the Meta adapter classifies HTTP errors into retryable/permanent/unknown. A timed-out send is recorded as `UNKNOWN` and never retried automatically (R43).
- **Conversation engine.** One transaction per inbound event; explicit action bindings (opaque tokens) route replies to the exact participation/question; commands (`STOP` has precedence) are parsed before question processing; foreground/background participation state is persisted so switching surveys never cross-wires answers (R15-R22, R31-R42).
- **Answers.** One canonical `answers` row per participation/question plus `answer_revisions` and `answer_selections`; the first accepted answer fixes `edit_expires_at = min(first + window, closes_at)`; row locks on the participation serialize concurrent replies (R31-R35).
- **Reporting.** Aggregates are computed from current canonical selections with explicit denominators (valid respondents; delivery-evidence intersection for response rate). Demographic breakdowns use the analysis profile frozen at participation start; cohorts under 5 respondents are suppressed for non-Admins (R46-R49).
- **Result sharing.** Admin-only after closure. One frozen aggregate snapshot per run, one broadcast, questions with fewer than 5 respondents withheld, template outside the 24-hour window, `View results` delivers the bound snapshot (R51-R54).

## Defaults and policies chosen

| Topic | Choice |
| --- | --- |
| Edit window | 120 s from the first accepted answer, never reset by edits, capped at survey close, 0 disables (R32-R34). Strictly less-than comparison at expiry. |
| Duration | 48 h from the *intended* opening time; range 1 h – 30 d. Explicit closing instant allowed for Admins. |
| Audience freeze | At scheduling/launch; permission is rechecked by the send policy gate immediately before every send (R24, R45). |
| Imports | Name and phone required; imported rows create contacts with **unknown** permission unless the staff member records a consent attestation for the file. Withdrawn contacts are never re-enabled by an import (R12, R14). |
| Contact uniqueness | Organization + normalized E.164. The same number may exist in two organizations with separate consent (R10). |
| Participant-initiated enrollment | Unknown senders get an enrollment prompt; permission is only granted after an affirmative reply; replies never authorize future campaigns by themselves (R20). |
| Service window | 24 h from the last verified inbound message. Free-form messages outside it are not sent; templates are used for invitations and results notices only (R45, R52). |
| Renderer routing | ≤3 short options → reply buttons; ≤10 → list; otherwise a single-choice Flow. Multiple selection always uses a Flow; ratings use a list 1-5 with optional endpoint labels (R16-R19). |
| Cohort threshold / share minimum | 5 respondents for both, documented as disclosure controls, not anonymity guarantees. |
| Export formula neutralization | Cells beginning with `= + - @ \t \r` are prefixed with `'`; phone numbers are kept as text in XLSX (R50). |
| Retention | Raw import bytes 24 h, raw webhook payloads 7 d, quarantine 7 d, action bindings 45 d; cleanup runs hourly from the sweep (R56). |
| Audit | Sensitive reads/exports/consent/retry/configuration changes are audited without personal data or selected answers (R06, R49). |
| Demo accounts | `admin@pilap.demo`, `manager@pilap.demo`, `viewer@pilap.demo` plus a second tenant `admin@lcf.demo`. Created only when `ALLOW_DEMO_BOOTSTRAP=true`, which the configuration rejects in live/production mode (R57). |
| Synthetic contacts | Seeded contacts carry `is_synthetic`; the live send policy refuses them unconditionally (R57). |

## Operational choices

- **Local stack**: Docker Compose with PostgreSQL 16, the Firebase Auth emulator (auth only, no Java), API, worker, a one-shot `bootstrap` service (migrations + idempotent seed) and nginx serving the dashboard on `127.0.0.1:8080` with `/api` proxied. Loopback-only port bindings.
- **Host development**: `pnpm dev` starts the emulator, migrates, seeds, and runs API/worker/web with the Angular dev server proxying `/api`.
- **Nest decorator metadata**: operational commands (`seed`, `seed:scale`, `sweep`, `run-once`, `retention`) run through the built worker bundle (`scripts/run-cli.ts`) because esbuild-based runners such as `tsx` do not emit decorator metadata.
- **Database reset**: `pnpm db:reset -- --yes` refuses non-local database hosts and live/production settings. Prisma's own guard additionally blocks AI-agent invocations of `migrate reset`.
- **Cloud path (not exercised)**: Cloud Run services for API and worker, Cloud SQL, Cloud Tasks pushing to `/internal/jobs/:id/execute` with OIDC, Cloud Scheduler calling `/internal/sweep`. See `DEPLOYMENT.md`.
- **Flow JSON**: version 7.0 assets without `data_api_version` (no data endpoint is used). `pnpm whatsapp:validate` checks structure, dynamic references, payload keys against the inbound parser, fixtures and template specs; Meta's builder/upload validation remains authoritative.

## Execution policy for this repository

The product owner authorized, in the implementation prompt for this build, committing, pushing the feature branch, opening a pull request, replying to review comments, creating tracking issues and resolving review threads. `AGENTS.md` §2 and `START-HERE.md` record that update. Merging, force-pushing, cloud provisioning, billing, real WhatsApp sends, Meta asset changes, Terraform and CI/CD remain prohibited.
